# PMIK SNS 데이터 분석 및 유효성 검사 종합 가이드

이 문서는 PMIK의 SNS 데이터를 효과적으로 분석하기 위한 **크롤링 데이터 검증, 피처 엔지니어링, 자연어 처리(NLP) 방법론**을 포괄적으로 다룹니다.

---

## 1. 데이터 수집 및 피처 유효성 검사 (Data & Feature Validation)

NLP 분석 이전에, 수집된 데이터(크롤링 결과물)와 생성된 피처(Feature) 자체가 신뢰할 수 있는지 검증해야 합니다. 쓰레기가 들어가면 쓰레기가 나옵니다(Garbage In, Garbage Out).

### 1.1. 크롤링 결과물 유효성 검사 (Data Validation)
크롤링 데이터는 불완전하거나 편향될 가능성이 높으므로 다음 항목을 반드시 점검해야 합니다.

1.  **완전성 (Completeness)**
    *   **결측치(Null) 비율**: 주요 컬럼(본문, 날짜, 작성자)에 비어있는 값이 얼마나 되는지 확인합니다. (예: 본문이 없는 게시물이 10% 이상이면 크롤링 로직 점검 필요)
    *   **기간 연속성**: 수집 기간(예: 1년) 동안 데이터가 없는 날짜가 있는지 확인합니다. 특정 기간에 서버 오류로 수집이 누락되었을 수 있습니다.
2.  **무결성 (Integrity)**
    *   **중복 제거**: 동일한 게시물이 중복 수집되었는지 `post_id`나 `url`로 확인합니다.
    *   **형식(Format) 준수**: 날짜 포맷, 숫자 컬럼에 문자 포함 여부 등을 체크합니다.
    *   **이상치(Outlier) 탐지**: 좋아요 수가 비정상적으로 높거나(매크로 의심), 본문 길이가 0이거나 너무 긴 경우를 식별합니다.
3.  **분포 확인 (Distribution Check)**
    *   **플랫폼별 분포**: 7개 플랫폼 간 데이터 불균형이 심한지 확인합니다. (특정 플랫폼 데이터가 너무 적으면 분석에서 제외하거나 가중치를 조정해야 함)
    *   **작성자 편향**: 특정 소수(헤비 유저)가 전체 데이터의 80%를 생성했는지 확인합니다. 이 경우 '일반적인 판매원'의 특징이 아닌 '특정 인물'의 특징이 될 수 있습니다.

### 1.2. 피처 유효성 검사 (Feature Validation)
NLP로 추출한 토픽 외에, 기존에 생성한 피처(길이, 해시태그 수 등)가 분석에 유효한지 검증합니다.

1.  **분산(Variance) 확인**
    *   모든 데이터의 값이 거의 같다면(예: 모든 게시물의 `video_count`가 0), 그 피처는 변별력이 없습니다. 분산이 0에 가까운 피처는 제거합니다.
2.  **상관관계(Correlation) 분석**
    *   **다중공선성(Multicollinearity)**: 피처끼리 너무 강한 상관관계(0.9 이상)가 있으면 중복입니다. (예: `content_length`와 `word_count`는 거의 같음 -> 하나만 선택)
    *   **타겟 상관관계**: 우리가 알고 싶은 결과(예: `engagement_score`)와 피처 간의 상관계수를 확인합니다. 상관계수가 너무 낮으면 유효하지 않은 피처일 수 있습니다.

## 2. 자연어 처리(NLP) 방법론

### 2.1. 왜 자연어 처리가 필요한가?
현재 사용 중인 `ContentTypeClassifier`는 사전 정의된 키워드 매칭 방식입니다. 이는 명확한 카테고리 분류에는 효율적이지만, 다음과 같은 한계가 있습니다:
- **숨겨진 패턴 발견 불가**: 사전에 정의하지 않은 새로운 홍보 트렌드나 고객의 니즈를 파악하기 어렵습니다.
- **문맥 파악의 한계**: 단순 키워드 매칭은 "추천하지 않습니다"와 "추천합니다"를 구별하기 어려울 수 있습니다.
- **데이터의 풍부함 활용**: 줄글 데이터에는 단순 키워드 이상의 감정, 인과관계, 스토리텔링 구조가 포함되어 있습니다.

NLP, 특히 토픽 모델링과 군집화(Clustering)를 도입하면 **"우리가 무엇을 모르는지 모르는(Unknown Unknowns)"** 영역, 즉 새로운 인사이트를 발견할 수 있습니다.

### 2.2. 추천 툴 및 라이브러리 (Python 생태계)

한국어 텍스트 분석을 위해 다음의 표준 라이브러리 조합을 추천합니다.

| 단계 | 추천 라이브러리 | 설명 |
| :--- | :--- | :--- |
| **형태소 분석** | **KoNLPy (Mecab, Okt)** | 한국어의 조사, 어미를 제거하고 명사/형용사만 추출하기 위해 필수입니다. 속도는 `Mecab`, 편의성은 `Okt`가 좋습니다. |
| **신조어 처리** | **Soynlp** | SNS 데이터 특성상 사전에 없는 신조어, 이모티콘 패턴 등을 학습 기반으로 토큰화하는 데 유용합니다. |
| **벡터화** | **Scikit-learn (TF-IDF)** | 단어의 빈도와 역문서 빈도를 고려하여 중요 단어를 수치화합니다. |
| **토픽 모델링** | **Gensim (LDA)** | 가장 전통적이고 해석이 용이한 토픽 모델링 기법입니다. |
| **최신 트렌드** | **BERTopic** | BERT 임베딩을 활용하여 문맥을 더 잘 파악하고, 동적인 토픽 모델링이 가능합니다. (강력 추천) |

### 2.3. 분석 프로세스 제안

1.  **전처리 (Preprocessing)**
    *   **정제**: URL, 이모티콘, 특수문자 제거 (기존 `post_processor.py` 활용 가능).
    *   **형태소 분석**: 불용어(Stopwords) 제거 및 명사(Noun) 추출. SNS 홍보글 특성상 '형용사(감성)'도 중요한 피처가 될 수 있습니다.
2.  **벡터화 (Vectorization)**
    *   TF-IDF 변환을 통해 단순 빈도가 아닌, 해당 문서에서만 특별히 많이 나오는 단어에 가중치를 둡니다.
3.  **모델링 (Modeling)**
    *   **LDA (Latent Dirichlet Allocation)**: 문서가 어떤 토픽들의 혼합으로 구성되어 있는지 확률적으로 추론합니다.
    *   **K-means Clustering**: 문서들을 벡터 공간상에서 거리가 가까운 것끼리 묶습니다.

## 3. 토픽 및 피처 유효성 검사 (Validation)

비지도 학습(Unsupervised Learning)은 정답(Label)이 없기 때문에 "얼마나 잘 되었나"를 판단하기 어렵습니다. 따라서 **정량적 지표**와 **정성적 평가**를 병행해야 합니다.

### 3.1. 정량적 지표 (Quantitative Metrics)

#### A. 토픽 모델링 (LDA 등) 평가
1.  **Perplexity (혼란도)**
    *   모델이 관측되지 않은 데이터를 얼마나 잘 예측하는지 나타냅니다.
    *   수치가 **낮을수록** 좋지만, 사람의 해석 가능성과 항상 일치하지는 않습니다.
2.  **Coherence Score (일관성 점수)** ⭐ *가장 중요*
    *   하나의 토픽 내에 묶인 단어들이 의미적으로 얼마나 유사한지를 측정합니다. (예: '화장품', '피부', '미백' vs '화장품', '축구', '주식')
    *   `Gensim`의 `CoherenceModel` (c_v measure)을 주로 사용합니다.
    *   수치가 **높을수록** 해석하기 좋은 토픽입니다.

#### B. 군집화 (K-means) 평가
1.  **Silhouette Score (실루엣 계수)**
    *   군집 내 데이터는 얼마나 가깝고(응집도), 다른 군집과는 얼마나 먼지(분리도)를 -1~1 사이 값으로 나타냅니다.
    *   **0.5 이상**이면 꽤 명확한 군집, 0.25 미만이면 군집 간 중복이 많음을 의미합니다.
2.  **Elbow Method**
    *   군집 수(K)를 늘려가며 오차 제곱합(SSE)이 급격히 줄어들다가 완만해지는 지점(팔꿈치)을 최적의 K로 선정합니다.

### 3.2. 정성적 평가 (Qualitative Evaluation)

수치만으로는 비즈니스 인사이트를 보장할 수 없습니다. 반드시 다음 과정을 거쳐야 합니다.

1.  **Word Intrusion Task (단어 침입 테스트)**
    *   사람(분석가)에게 토픽의 상위 단어 5개 중, 무작위로 섞인 '가짜 단어' 1개를 찾아내게 합니다. 쉽게 찾아낼수록 토픽이 명확한 것입니다.
2.  **도메인 전문가 리뷰**
    *   도출된 토픽(예: "다이어트 챌린지", "보상 플랜 설명")이 실제 현장의 영업 방식과 매칭되는지 확인합니다.
3.  **시각화 (Visualization)**
    *   `pyLDAvis`: LDA 모델을 인터랙티브하게 시각화하여 토픽 간 거리와 키워드 분포를 확인합니다. 토픽 원들이 서로 겹치지 않고 고르게 퍼져 있을수록 좋습니다.

### 3.3. 비즈니스 유효성 검증 (Business Validation)

가장 실질적인 검증 방법입니다.

*   **상관관계 분석**: 도출된 '토픽 비중'과 실제 '좋아요 수', '공유 수', '댓글 수' 간의 상관관계를 분석합니다.
    *   *예: "체험 후기" 토픽 비중이 높을수록 댓글 수가 많다.* -> 유효한 피처임.
*   **A/B 테스트 제안**: 분석 결과 "비포/애프터" 토픽이 반응이 좋다면, 이를 강화한 콘텐츠를 시범 운영하여 성과를 측정합니다.

## 4. 요약 및 제언

1.  **Step 1**: `KoNLPy`와 `Scikit-learn`을 사용하여 텍스트 데이터를 벡터화하십시오.
2.  **Step 2**: `LDA`로 토픽을 추출하고 `Coherence Score`로 최적의 토픽 개수를 찾으십시오.
3.  **Step 3**: `pyLDAvis`로 시각화하여 토픽이 직관적으로 구분되는지 확인하십시오.
4.  **Step 4**: 도출된 토픽을 기존 메타 데이터(좋아요, 날짜 등)와 결합하여 "어떤 토픽이 반응을 이끄는지" 분석하십시오.

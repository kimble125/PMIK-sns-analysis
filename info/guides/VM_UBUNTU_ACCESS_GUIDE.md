# Ubuntu 및 VM 접속 가이드

## 🐧 Ubuntu란?

### 정의
**Ubuntu**는 Linux 기반의 오픈소스 운영체제(OS)입니다.

### 주요 특징
- **무료**: 완전 무료로 사용 가능
- **안정성**: 서버 운영에 최적화
- **보안**: 정기적인 보안 업데이트
- **경량**: Windows보다 적은 리소스 사용
- **커뮤니티**: 방대한 개발자 커뮤니티

### Windows vs Ubuntu

| 항목 | Windows | Ubuntu |
|------|---------|--------|
| 라이선스 | 유료 | 무료 |
| 서버 용도 | Windows Server (비쌈) | Ubuntu Server (무료) |
| 리소스 | 많이 사용 | 적게 사용 |
| 보안 | 바이러스 취약 | 상대적으로 안전 |
| 명령어 | cmd, PowerShell | bash, zsh |
| 패키지 관리 | 수동 설치 | apt (자동) |

### 왜 VM에서 Ubuntu를 사용하나?

1. **비용 절감**: Windows Server 라이선스 불필요
2. **성능**: 같은 사양에서 더 빠른 성능
3. **안정성**: 24/7 운영에 적합
4. **자동화**: 스크립트 및 크론잡 활용 용이
5. **개발 환경**: Python, Node.js 등 개발 도구 설치 간편

## 🔐 Ubuntu 비밀번호란?

### 1. Ubuntu 사용자 계정 비밀번호

#### 개념
- Ubuntu OS 내에서 사용하는 **로컬 사용자 계정**의 비밀번호
- 현재 VM의 사용자: `pmi`
- 이 비밀번호로 `sudo` 명령어 실행 가능

#### 역할
```bash
# sudo 명령어 사용 시 필요
sudo apt update          # 비밀번호 입력 필요
sudo systemctl restart   # 비밀번호 입력 필요
sudo nano /etc/hosts     # 비밀번호 입력 필요
```

#### 비밀번호 확인 방법
- ❌ **저장되어 있지 않음**: Ubuntu 비밀번호는 암호화되어 저장되며, 평문으로 확인 불가
- ✅ **알고 있어야 함**: VM 생성 시 설정한 비밀번호를 기억하거나 기록해야 함
- ✅ **SSH Key 사용**: 비밀번호 대신 SSH 키로 접속 가능 (현재 방식)

## 🔑 SSH 접속 방식

### 현재 사용 중인 방식: SSH Key 인증

```bash
# 현재 접속 방법
ssh crawler  # 또는 ssh analyst
```

#### SSH Key 인증 원리
1. **공개키(Public Key)**: VM의 `~/.ssh/authorized_keys`에 저장
2. **개인키(Private Key)**: 로컬 맥북의 `~/.ssh/` 폴더에 저장
3. **인증 과정**: 개인키로 서명 → VM이 공개키로 검증 → 접속 허용

#### 장점
- ✅ 비밀번호 입력 불필요
- ✅ 더 안전함 (키 파일 없으면 접속 불가)
- ✅ 자동화 가능 (스크립트에서 사용)

#### SSH Config 설정 확인
```bash
# 로컬 맥북에서 확인
cat ~/.ssh/config
```

예상 내용:
```
Host crawler
    HostName 20.x.x.x
    User pmi
    IdentityFile ~/.ssh/azure_vm_key
    Port 22

Host analyst
    HostName 20.y.y.y
    User pmi
    IdentityFile ~/.ssh/azure_vm_key
    Port 22
```

## 🌐 Azure Portal 비밀번호 vs Ubuntu 비밀번호

### 비교표

| 항목 | Azure Portal 비밀번호 | Ubuntu 비밀번호 |
|------|----------------------|----------------|
| **용도** | Azure 웹사이트 로그인 | VM 내부 sudo 명령어 |
| **관리 위치** | Azure AD (클라우드) | VM 내부 (/etc/shadow) |
| **사용 시점** | Azure Portal 접속 시 | VM 내부에서 관리자 권한 필요 시 |
| **변경 방법** | Azure Portal에서 변경 | VM 내부에서 `passwd` 명령어 |
| **연관성** | ❌ 완전히 별개 | ❌ 완전히 별개 |

### 상세 설명

#### 1. Azure Portal 비밀번호
```
사용 예시:
1. 웹 브라우저로 portal.azure.com 접속
2. 이메일: your-email@company.com
3. 비밀번호: [Azure Portal 비밀번호] 입력
4. VM 관리, 리소스 확인 등
```

**역할**:
- Azure 클라우드 서비스 관리
- VM 생성/삭제/설정
- 비용 확인
- 네트워크 설정 등

#### 2. Ubuntu 비밀번호 (VM 내부)
```
사용 예시:
1. SSH로 VM 접속: ssh crawler
2. 관리자 권한 필요한 명령어 실행
3. sudo apt update
4. [Ubuntu 비밀번호] 입력 (pmi 계정 비밀번호)
```

**역할**:
- VM 내부에서 시스템 설정 변경
- 패키지 설치/업데이트
- 서비스 재시작
- 파일 권한 변경 등

## 🔍 현재 상황 분석

### Q1: Ubuntu 비밀번호를 알고 있나요?

**확인 방법**:
```bash
# VM에 접속해서 sudo 명령어 실행
ssh crawler
sudo whoami
# 비밀번호 입력 요청이 나오면 → 비밀번호 필요
# 바로 실행되면 → 비밀번호 없이 설정됨 (또는 최근에 입력함)
```

**가능한 상황**:

#### 상황 1: 비밀번호를 알고 있음
- ✅ VM 생성 시 설정한 비밀번호를 기억하고 있음
- ✅ 문서에 기록되어 있음
- ✅ 팀원과 공유되어 있음

#### 상황 2: 비밀번호를 모름
- ⚠️ SSH Key로만 접속 중
- ⚠️ sudo 명령어 사용 불가 (또는 제한적)
- ⚠️ 시스템 설정 변경 어려움

**해결 방법**:
```bash
# 방법 1: Azure Portal에서 비밀번호 재설정
# Azure Portal → VM → Reset password

# 방법 2: sudo 권한 확인
ssh crawler
sudo -l  # sudo 권한 확인

# 방법 3: passwordless sudo 설정 (권장하지 않음)
# 보안상 위험하므로 비추천
```

## 📋 비밀번호 관리 권장사항

### 1. 비밀번호 정책

#### Azure Portal 비밀번호
- **복잡도**: 대문자, 소문자, 숫자, 특수문자 포함
- **길이**: 최소 12자 이상
- **MFA**: 다중 인증 활성화 권장
- **관리**: 비밀번호 관리자 사용 (1Password, LastPass 등)

#### Ubuntu 비밀번호
- **복잡도**: 최소 8자 이상
- **관리**: 팀 내부 안전한 곳에 기록
- **공유**: 필요한 팀원에게만 공유
- **변경**: 정기적 변경 (3~6개월)

### 2. 접속 방법 우선순위

```
1순위: SSH Key 인증 (현재 방식) ✅
  - 가장 안전
  - 비밀번호 불필요
  - 자동화 가능

2순위: SSH Key + Ubuntu 비밀번호
  - SSH Key로 접속
  - sudo 명령어는 비밀번호 필요
  - 권장 방식

3순위: 비밀번호만 사용 ❌
  - 보안 취약
  - 비추천
```

## 🛠️ 실습: 비밀번호 상태 확인

### Step 1: SSH 접속 확인
```bash
# 로컬 맥북에서
ssh crawler

# 성공하면 → SSH Key 인증 작동 중 ✅
# 비밀번호 요청하면 → SSH Key 문제 ⚠️
```

### Step 2: Sudo 권한 확인
```bash
# VM 내부에서
sudo whoami

# 비밀번호 입력 요청:
# [sudo] password for pmi: _____
# → 비밀번호 필요 (알고 있어야 함)

# 바로 "root" 출력:
# → 비밀번호 없이 sudo 가능 (또는 최근 입력)
```

### Step 3: 비밀번호 변경 (필요 시)
```bash
# 현재 비밀번호를 알고 있는 경우
passwd

# 현재 비밀번호를 모르는 경우
# → Azure Portal에서 재설정 필요
```

## 🔐 보안 모범 사례

### DO ✅
1. **SSH Key 사용**: 비밀번호보다 안전
2. **MFA 활성화**: Azure Portal에 다중 인증 설정
3. **비밀번호 관리자**: 안전한 곳에 저장
4. **정기 변경**: 3~6개월마다 비밀번호 변경
5. **최소 권한**: 필요한 권한만 부여
6. **로그 모니터링**: 접속 기록 정기 확인

### DON'T ❌
1. **평문 저장**: 비밀번호를 코드나 문서에 평문으로 저장
2. **공개 공유**: Slack, 이메일 등 공개 채널에 비밀번호 공유
3. **단순 비밀번호**: "password123" 같은 단순 비밀번호 사용
4. **재사용**: 다른 서비스와 같은 비밀번호 사용
5. **Passwordless sudo**: 보안상 위험

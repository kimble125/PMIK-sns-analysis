## 🚨 문제 요약

주말 동안 Azure VM 크롤러가 예기치 않게 중단되었으며, 조사 결과 **ACL(Access Control List) 네트워크 제한**으로 인한 접근 차단이 원인으로 확인되었습니다.

### 시간대
- **발생 시점**: 주말 (2025년 11월 16일~17일 추정)
- **발견 시점**: 2025년 11월 18일
- **영향 기간**: 약 1~2일

### 증상
- VM 크롤러 프로세스 중단
- VM 접속 불가
- 데이터 수집 중단

---

## 🔍 원인 분석

### 근본 원인
**ACL(Access Control List) 네트워크 정책**
- Azure VM에 설정된 네트워크 보안 그룹(NSG)이 **회사 네트워크 IP 대역**으로만 접근을 제한
- 회사 네트워크 외부에서의 SSH 접속 차단
- 크롤러 프로세스가 외부 API 호출 시 차단 가능성

### 기술적 세부사항
```
문제: Network Security Group (NSG) 규칙
- 허용: 회사 네트워크 IP 대역 (예: 203.x.x.x/24)
- 차단: 그 외 모든 IP 주소
- 영향: SSH(22), HTTP(80), HTTPS(443) 포트
```

---

## 💥 영향 범위

### 1. 데이터 수집 중단
- 네이버 블로그 크롤러 중단
- 예상 수집 손실: 약 2일치 데이터

### 2. 모니터링 불가
- VM 상태 확인 불가
- 로그 접근 불가
- 실시간 대응 불가

### 3. 업무 연속성 저해
- 주말/휴일 원격 작업 불가
- 긴급 상황 대응 지연

---

## ✅ 해결 방안

### 즉시 조치 (단기)
1. **VPN 사용**
   - 회사 VPN 연결 후 VM 접속
   - 모든 팀원에게 VPN 접속 정보 공유

2. **허용 IP 추가**
   - 재택근무 IP 주소를 NSG 허용 목록에 추가
   - 주요 팀원의 고정 IP 등록

### 근본적 해결 (장기)
1. **Azure Bastion 도입**
   ```
   장점:
   - 브라우저 기반 SSH 접속
   - NSG 규칙 우회
   - 추가 보안 계층
   ```

2. **VPN Gateway 구축**
   - Point-to-Site VPN 설정
   - 안전한 원격 접속 환경 구축

3. **조건부 접근 정책**
   - Azure AD 조건부 접근 사용
   - MFA(다중 인증) 적용
   - IP 제한 완화 + 인증 강화

4. **프로세스 자동화 개선**
   - PM2 등 프로세스 매니저 도입
   - 자동 재시작 및 알림 설정
   - 크래시 시 자동 복구

## 📝 교훈 및 개선점

### 배운 점
1. **네트워크 정책 이해 부족**
   - ACL/NSG 설정에 대한 사전 이해 필요
   - 네트워크 제한 사항 문서화 필요

2. **모니터링 체계 미흡**

   - 알림 시스템 부재

3. **재해 복구 계획 부재**

2. **자동화 강화**

3. **교육 및 공유**

   - VPN 사용법 공유
   - 장애 대응 훈련
